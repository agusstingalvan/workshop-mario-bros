# Spec-Driven Development

Use a spec to define a small change, a plan to inspect the technical path, and evidence to support the result. Specs are human-approved contracts, not automatic code-generation requests.

## Working structure

- Copy a template from `templates/` into `specs/`, `plans/`, or `evidence/`; do not edit the template for a single change.
- Use the same sortable identifier across related records, for example `001-player-lives.md`.
- Link the approved spec from its plan, and link the plan and spec from its evidence.
- Keep records with the code and review them together.
