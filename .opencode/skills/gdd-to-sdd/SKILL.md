# GDD to SDD

Read the GDD and existing specs before responding. Identify the player fantasy, design pillars, core loop, mechanics, entities, progression, UX, and constraints.

Ask questions that help the person turn one design intention into a small, testable spec. Do not create numbered specs, scenes, assets, or code automatically.

When asked for alignment, produce a report with:

- GDD elements covered by specs.
- GDD elements without an implementation definition.
- Specs without explicit support in the GDD.
- Contradictions, assumptions, and decisions that need human review.
